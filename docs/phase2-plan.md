## 一、二期待实现功能

### F5. 微信支付真实接入（高优先级）

**背景**：当前 `cloudfunctions/order/actions/pay.js` 是开发模式模拟支付，直接设置 `status = 'paid'` 并返回 `{ simulated: true }`。需要对接微信支付商户平台完成真实支付。

**实现内容**：

**F5.1 云函数改造**
- `pay.js` 改为调用 `cloud.cloudPay.unifiedOrder()` 统一下单
- 生成微信支付参数（timeStamp/nonceStr/package/signType/paySign）
- 返回支付参数给前端调用 `wx.requestPayment`
- 支付成功后通过云回调确认支付状态
- 保留开发模式开关（环境变量判断）

**F5.2 前端改造**
- `miniprogram/utils/payment.js` 的 `payOrder()` 去除模拟逻辑
- 接入 `wx.requestPayment` 真实调起微信支付
- 支付失败处理（余额不足/取消/网络异常）

**F5.3 前置条件**
- 微信商户平台申请商户号
- 商户号与小程序 AppID 绑定
- 云开发后台配置商户号关联

---

### F6. 管理员审核页面（高优先级）

**背景**：`cloudfunctions/coach/actions/approve.js` 和 `reject.js` 已完整实现，包含管理员权限校验（检查 `admin` 角色）和通知推送。但**前端没有任何管理员管理页面**，目前只能通过云开发控制台直接调用云函数来审核。

**实现内容**：

| 页面 | 功能 |
|------|------|
| 教练审核列表 | 展示所有 `status='pending'` 的教练申请（姓名/特长/年限/报价/认证图片），支持分页 |
| 审核详情 | 展开查看完整申请资料（含所有认证图片预览），审批按钮（通过/驳回 + 驳回理由输入） |
| 审核历史 | 查看已处理的申请记录（通过/驳回），支持按状态筛选 |

**权限控制**：
- 云函数层已有 `admin` 角色校验（`getMyInfo` 返回 `role` 字段）
- 前端页面入口仅在用户 `role` 包含 `admin` 时显示
- 可在个人中心增加"管理后台"入口

---

### F7. 退款功能（中优先级）

**背景**：数据库 schema 已定义订单 status 包含 `refunded`，`cancel()` 只支持取消待付款/已付款订单（退还排期但不退款）。缺少完整的退款流程。

**实现内容**：

**F7.1 云函数**
- 新增 `cloudfunctions/order/actions/refund.js`
  - 校验订单归属和状态（仅 `paid` 可退款）
  - 调用排期释放
  - 设置 `status='refunded'`，记录退款时间和金额
  - 有真实支付时调用微信退款接口
  - 发送退款通知

**F7.2 前端**
- 订单详情增加"申请退款"按钮（仅已支付且未完成订单）
- 退款确认弹窗（二次确认）
- 退款成功后状态联动更新

---

### F8. 评价回复功能（中优先级）

**背景**：`reviews` 表 schema 已定义 `reply` 字段 `{ content, replied_at }`，但云函数和前端均未实现回复功能。

**实现内容**：

**F8.1 云函数**
- 新增 `cloudfunctions/review/actions/reply.js`
  - 校验回复人是否为评价目标的教练/场地主
  - 更新 `reply` 字段
  - 发送通知给评价者

**F8.2 前端**
- 评价详情/列表展示已有回复（如有）
- 教练端可以看到自己收到的评价
- 回复输入弹窗

## 四、二期完成后的状态

二期交付后，商业化能力完整：

```
用户预约教练 → 微信支付（真实扣款）→ 完成服务 → 评价
教练收到评价 → 回复评价
订单异常 → 申请退款 → 审核退款（或自动退款）
管理员 → 审核教练申请 → 查看审核历史
```

项目从 MVP 阶段进入**可运营阶段**。
