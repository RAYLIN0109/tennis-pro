## 二、一期待实现功能

### F1. 活动模块 -- 云函数 + 前端（高优先级）✅

**背景**：`activity` 云函数 3 个 action（list/detail/create）全部返回 mock 数据，前端 3 个页面（列表/详情/创建）全部是空壳。数据库 schema 已完整设计（`collections.json` 中定义了 `activities` 表的全部字段和索引）。

**实现内容**：

**F1.1 云函数重构 ✅**
- 创建 `cloudfunctions/activity/actions/` 目录，按项目规范拆分为：
  - `list.js` — 分页查询，支持按 type/status/creator 筛选，按 start_time 排序
  - `detail.js` — 单条详情，关联查询 creator 用户信息（昵称/头像），同时返回参与者列表
  - `create.js` — 创建活动，校验必填字段（type/title/start_time/end_time/location），自动设置 creator_id = OPENID，status = 'open'
  - `join.js` — 报名参加活动
  - `leave.js` — 退出活动
- `index.js` 改为 switch 路由分发（参考 coach/user 风格）
- 弃用 mock 返回代码

**F1.2 前端页面实现 ✅**

| 页面 | 当前状态 | 目标 |
|------|---------|------|
| `pages/activity/list/index` | ✅ 已完成 | 真实数据驱动，分页加载，支持按 type 筛选（约球/观赛/我的活动），下拉刷新，触底加载更多 |
| `pages/activity/detail/index` | ✅ 已完成 | 展示活动详情（标题/时间/地点/费用/参与人数/创建者），支持"我要参加"按钮 |
| `pages/activity/create/index` | ✅ 已完成 | 完整表单：类型选择、标题、描述、时间、地点、人数限制、费用、标签 |

**F1.3 服务层更新 ✅**
- `miniprogram/services/activity.js` 方法保持，底层自动对接新的云函数

## 四、一期完成后的状态

一期交付后，核心体验链路为：

```
首页 → 浏览活动列表 → 查看活动详情 → 参加活动
     → 创建活动 → 等待其他人加入
     → 约教练 → 预约时段 → 支付 → 完成后评价
     → 查看通知（订单状态 / 审核结果 / 活动提醒）
```

所有页面均接入真实数据，不再有"即将开放"的占位提示（除网球圈仍需二期）。
